# M5-3 集成架构:一个界面装下全部，且急停分四层

## 1. 六个部件怎么拧在一起

```
   裁判指令(HTTP /api/referee/* 或话题)      操作员(Web / 语音 / 按键)
                 │                                      │
        ┌────────▼────────┐                   ┌─────────▼─────────┐
        │ referee_bridge  │                   │  terminal_app     │
        │  3-2-1 倒计时    │                   │  do_action() 总控 │
        │  PAUSE/STOP 解析 │                   │  10Hz 快照        │
        └────────┬────────┘                   └─────────┬─────────┘
                 │ 状态回报                             │
                 ├──────────────▶ 界面(SSE)             │
                 │                                      ├──▶ race_bridge(包 M5-1 状态机)
                 └──▶ 状态机 start/pause                ├──▶ hot_switch(切参数/模型)
                                                        ├──▶ safety(分层急停)
   watchdog(拔相机 → 降级) ──▶ 审计 + 语音 ◀─────────────┤
                                                        └──▶ audit(哈希链)
```

**没有一个部件直接改别的部件的状态**，全部经过 `terminal_app.do_action()`。
这样界面上每个按钮、语音、按键最终都落到同一个动作分发点，
**审计只需要在一处埋点**，不会漏记。

## 2. 为什么复用 M5-1 而不是重写状态机

`race_bridge.py` 在 M5-1 的 `StateMachine` **外面**套了一层 guard，
而不是复制一份状态机：

- M5-1 的边界是"节点只管执行，状态机只管调度"，这条边界不能破；
- 操作员的暂停/跳过/急停属于**外部干预**，用包装（guard）插入；
- 内核一行没改，M5-1 的 29 个用例仍然全过。

答辩讲"复用而非复制"就落在这里：同一份内核，M5-2 用它跑仪表盘，
M5-3 用它跑比赛流程，行为一致。

## 3. 分层急停（`host_side/safety.py`）

题面点名的最容易翻车处：**只发一条零速度不够**。

| 层 | 动作 | 不做的后果 |
| :-- | :-- | :-- |
| ① 指令层 | 发零速度 `/cmd_vel` | 常规停车，但别的发布者会覆盖 |
| ② 话题层 | 发 `/emergency_stop` | 底盘不知道自己该锁住 |
| ③ 控制器层 | 置使能位为 0 | 控制器超时恢复后车又开始走 |
| ④ 记录层 | 黑匣子 + 审计 | 事后无法追责 |

响应顺序：**先锁死（①②），再记录（④）**。
如果先写日志再停车，日志里的时间会比实际停车晚，
复盘时会误判"审计了但没停住"。

**解除必须人工**：`sim.estopped` 置位后不会自动清，
必须走 `soft_reset`（软复位）或重启。自动恢复是明确禁止的。

## 4. 热切怎么做到不重启

- **参数**：`ros2 param set` 级别的操作，节点侧靠参数回调即时生效；
- **模型**：感知节点暴露"换模型"服务，加载成功才替换指针，失败则保留旧模型（可回滚）；
- **验证方式**：现场看 **PID 未变** + `switch_log.csv` 有记录 + 参数真的生效。

本实现用 `hot_switch.py` 里的 `HotSwapManager` 模拟这两条路径，
每次切换都写 `switch_log.csv`（时间/旧值/新值/操作人）并同步落一条审计。

**滑块防抖**：连续拖动时只在末尾值落一次记录，避免把参数服务打爆。

## 5. 原子级暂停

"暂停"不能把正在执行的节点从中间切断（那会留下半成品状态）。
实现上 `race_bridge.pause()` 置一个闸门标志，**在节点边界**检查：

- 当前节点跑完 → 检查闸门 → 停；
- 恢复时从下一个节点继续，已完成的不重跑。

这也是为什么暂停能"立即生效但不会撕裂"：等待时间最多一个节点。

## 6. 端口与共存

| 服务 | 端口 | 说明 |
| :-- | :-- | :-- |
| M5-2 仪表盘 | 8080 | 看全栈健康度 |
| M5-3 终端 | **8081** | 裁判/操作入口 |

现场两者**同时跑**，所以端口必须错开。默认值已写死在
`host_side/operator_terminal.py` 的 argparse 里，不需要现场加参数。

## 7. 已知取舍

- 未接真实 ROS2：`referee_bridge` 的指令来源是 HTTP，真实部署换成话题订阅即可，
  内部 `feed()` 通道不变；
- 语音唤醒词用关键词匹配模拟，真实部署接 `vosk`/`sherpa-onnx` 的离线识别，
  且**急停类动作必须二次确认**，防止误识别（题面明确禁止语音直接触发急停）。
