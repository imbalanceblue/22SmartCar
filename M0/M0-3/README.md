## 一、缺陷清单（问题报告主体）

> 格式：哪里有问题（行号/变量）→ 现象 → 原因（原理层面）→ 怎么解决。
> 行号为**原始脚本**中的行号；修复按 git 提交顺序排列，每修一个提交一次。

| # | 位置 | 现象 | 原因（原理） | 解决 |
| :-: | :-- | :-- | :-- | :-- |
| 1 | 原第 37 行 `row["Value"]` | `KeyError: 'Value'`，程序在第 1 条数据处崩溃 | csv 表头是 `time,value`（小写）；字典键**区分大小写**，`"Value"` ≠ `"value"`，取不到键即抛 KeyError | 改为 `row["value"]`。**必须最先修**：程序死在第 37 行，后面所有缺陷都被掩盖 |
| 2 | 原第 61 行 `os.path.join("/", "out", ...)` | `FileNotFoundError: '/out/cleaned_data.csv'` | `os.path.join` 以 `"/"` 开头拼成了**绝对路径**（根目录下 out 目录不存在）。`open(...,"w")` 只能创建**文件**，不会创建路径上缺失的**目录** | 输出路径改为当前工作目录的 `cleaned_data.csv`（也符合接口契约） |
| 3 | 原第 50~53 行标准差计算 | `std = 0.0000`，明显荒谬（60 条起伏明显的数据标准差不可能是 0） | 代码累加的是**偏差本身** `acc += (v - mean)`。而偏差有正有负，数学上**偏差之和恒等于 0**（Σvᵢ - n·v̄ = 0），所以 `acc/n` 永远是 0 | 对照定义 `std = sqrt(Σ(v-mean)²/n)` 补两处：累加时**平方** `(v-mean)**2`，除完**开方** `math.sqrt(...)`。修复后 std = 18.5033，与 numpy 交叉验证一致 |
| 4 | 原第 56~58 行离群值判定 | 只剔除偏大的值，**偏小的离群值永远漏剔** | 条件写成 `v > mean + 2*std`，没有 `abs()`。数学上离群值应同时存在于两侧 | 判定改为 `abs(v - mean) > 2 * std`（保留侧为 `abs(v-mean) <= 2*std`） |
| 5 | 原第 56~58 行 `for v in data: data.remove(v)` | **不报错，但漏删**——即使有多个离群值，也只会删掉一部分 | **边遍历边修改同一列表**：for 循环靠内部索引逐个前进，`remove()` 删掉一个元素后，后面的元素整体前移一位，下一次迭代索引 +1，导致**紧随被删元素之后的元素被跳过检查**。这类错误的特征是"程序不报错、结果悄悄不对" | 不再边遍历边删。新建独立循环把合格数据收进 `cleaned` 列表（遍历与修改分离），同时与 time 用 `zip` 配对 |
| 6 | 原第 28、65 行 `cleaned` | `清洗后剩余 0 条`，`cleaned_data.csv` 永远只有表头 | `cleaned = []` 创建后**全文无任何代码向其添加元素**（被剔除的数据也没有存回去），所以输出循环永远写不出数据 | 清洗逻辑负责向 `cleaned` 填充合格数据（含 time 配对） |
| 7 | 原第 64~66 行输出 | `cleaned_data.csv` 只有 value 一列，与表头 `time,value` 两列不符（且数据没有配回自己的时间戳） | 清洗时只保留了 value，time 丢弃 | 清洗按 `(time, value)` 元组配对保留（`zip(times, values)`），输出 `writer.writerow([t, v])` |
| 8 | 整体结构 | 异常输入（文件不存在/空文件/列名错/非数值）全部直接 `Traceback` 崩溃；不支持命令行参数，路径写死 | 无函数封装、无异常处理、无 CLI | 重构为 `load_data` / `analyze` / `clean` / `main` 四个函数；`argparse` 提供 `--input` / `--output`（带默认值）；入口 `try/except` 统一输出人话错误到 stderr 并 `sys.exit(1)` |

### 缺陷之间的依赖顺序（题目要求说明）

```
缺陷1(列名) ──必须先修──→ 否则程序死在读取阶段,2~7 全部不可见
缺陷2(输出路径) ──其次──→ 否则程序死在写文件阶段,3(标准差)的荒谬输出看不到
缺陷3(std公式) ──再次──→ std=0 会使离群值阈值失效,4 的现象被污染
缺陷4/5/6/7(清洗与输出) ──一起修──→ 三者纠缠在同一处逻辑(cleaned 从未被填充+边遍历边删+缺绝对值+缺time)
缺陷8(工程化) ──最后──→ 功能修对之后再补 CLI 与异常处理(先对再好)
```

**核心体会**：排错不是看到什么修什么 —— 前面的缺陷会**掩盖**后面的现象（本例中列名 bug 挡住了全部 6 个后续缺陷），修一个才能看见下一个。这也是"每修一个提交一次"的意义：git 历史就是这个多米诺过程本身。

## 二、接口契约与验收结果

### 运行方式

```bash
# 无参数(默认读写当前目录的 sensor_data.csv / cleaned_data.csv)
python3 sensor_analyzer.py

# 全参数
python3 sensor_analyzer.py --input sensor_data.csv --output cleaned_data.csv

# 异常输入示例
python3 sensor_analyzer.py --input 不存在.csv        # → 人话错误 + 退出码 1
```

### 实测输出（正常数据，n=60）

```
共读取 60 条数据
均值 mean = 50.4315
标准差 std = 18.5033
清洗后剩余 57 条
已保存到 cleaned_data.csv
```

std = 18.5033 与 `numpy.std` 交叉验证一致（总体标准差口径，除以 n）。
被剔除的 3 条均为**偏小**离群值（低于 mean - 2*std ≈ 13.4）—— 恰好是原脚本「只剔大不剔小」漏掉的那批。

### 异常输入实测（考官会喂的清单）

| 输入 | 实测结果 | 退出码 |
| :-- | :-- | :-: |
| 不存在的文件路径 | `错误: 找不到文件 不存在.csv` | 1 |
| 完全空文件 | `错误: 输入文件为空: ...` | 1 |
| 空文件(仅表头) | `错误: 数据为空(只有表头): ...` | 1 |
| 列名不是 time/value | `错误: csv 缺少列 ['value'],实际列为: ['time','VALUE']` | 1 |
| value 列含非数值 | `错误: 第 N 行: 无法把 time=... value=... 转为数字` | 1 |
| 全部数值相同(零方差) | 正常输出 mean/std=0.0000，stderr 提示"跳过离群值剔除"，不崩 | 0 |
| 不提供任何参数 | 使用默认路径正常运行 | 0 |

所有异常均输出**一句话人话错误到 stderr**，无任何 Traceback。
