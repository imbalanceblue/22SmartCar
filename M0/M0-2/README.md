## 二、输入文件格式

### config.yaml

| 字段 | 必填 | 说明 |
| :-- | :-: | :-- |
| `input_csv` | 是 | 数据文件路径。相对路径以配置文件所在目录为基准 |
| `columns.x` | 是 | 参与计算的第一个数值列列名 |
| `columns.y` | 是 | 参与计算的第二个数值列列名 |

示例：

```yaml
input_csv: "sample_data.csv"
columns:
  x: "sensor_a"
  y: "sensor_b"
```

### 数据 csv

- 表头必须包含 config 中 `columns.x` / `columns.y` 指定的列名，否则报错并列出实际列名
- 这两列的值必须可转换为小数；其他列（如 `timestamp`、`note`）随意
- 空文件（仅表头）会被人话提示拒绝，不会崩溃

## 三、输出结果的含义

| 输出 | 含义 |
| :-- | :-- |
| `n` | 参与计算的样本数 |
| `mean_x` / `mean_y` | 两列各自的算术平均值 |
| `r` | 皮尔逊相关系数，取值范围 [-1, 1] |

`r` 的解读：

| r | 含义 |
| :-- | :-- |
| 1 | 完全正相关（同增同减，严格线性） |
| 0.5 左右 | 中等正相关 |
| 0 | 无线性相关 |
| -1 | 完全负相关 |

样例数据（n = 40）实测输出：

```
n = 40
mean_x = 49.437825
mean_y = 43.310725
r = 0.5634747254524842
```

### 异常情况

任何异常输入都以可读错误信息 + 非 0 退出码结束，错误信息输出到 stderr，不出现 Traceback：

| 场景 | 提示 | 退出码 |
| :-- | :-- | :-: |
| 配置文件不存在 | `错误:找不到文件 xxx.yaml` | 1 |
| csv 文件不存在 | `错误:找不到文件 xxx.csv` | 1 |
| 空数据 / 仅表头 | `错误:数据为空,无法计算相关系数` | 1 |
| 列名不匹配 | `错误:csv 中没有列 'x' 或 'y',实际列为: [...]` | 1 |
| 某列方差为 0 | `错误:某列方差为 0,相关系数无定义` | 1 |
| 单元格非数值 | `错误:第 2 行: 无法把 x=abc 或 y=3 转为数字` | 1 |
| 未提供任何配置文件参数 | usage + 参数说明 | 2 |

## 四、相对原脚本的改动

| # | 原问题 | 现象 / 原因 | 修复 |
| :-: | :-- | :-- | :-- |
| 1 | **相关系数公式分母漏开方**（原第 44 行） | 分母 `dx * dy` 是两个二阶量（偏差平方和）相乘，成了四阶量，与分子 `prod`（二阶量）量纲不匹配。输出 `r = 0.000156`，与数据肉眼可见的正相关矛盾（numpy 标准答案 0.5635，相差约 3600 倍） | `denom = math.sqrt(dx * dy)`，使分母成为 σx·σy 的量纲。修复后 r = 0.5634747，与 `numpy.corrcoef` 一致 |
| 2 | 全局变量 + 顶层流水账，无函数封装 | 无法复用、无法单元测试 | 拆分 `load_config` / `load_columns` / `pearson_r` / `main`，`pearson_r` 为纯函数 |
| 3 | 读文件未用 `with` | 异常时文件句柄不关闭 | 全部改为 `with open(...)` |
| 4 | 无任何异常处理 | 文件缺失、空数据、坏数据直接 Traceback 崩溃 | 6 类异常统一处理，错误走 stderr + `sys.exit(1)` |
| 5 | 无 `if __name__ == "__main__"` 保护 | 被 import 时会误执行主流程 | 补上入口保护，配合顶层 `try/except` 统一出口 |
| 6 | `CONFIG_PATH` 写死，不支持参数 | 换配置文件必须改源码 | `argparse` 支持 `--config` 与位置参数两种写法 |
| 7 | csv 相对路径基准错误 | 从非 M0-2 目录调用时找不到数据文件 | `Path(config_path).resolve().parent` 为基准拼接 csv 路径，两种调用基准均实测通过 |
| 8 | `n = 0` 时除零、零方差时结果无定义 | 崩溃或产生无意义输出 | 显式 `raise ValueError` / `ZeroDivisionError` 并给出人话提示 |
| 9 | 无类型标注、无文档字符串、无依赖说明 | 队友无法上手 | 补齐 docstring；README 写明依赖与运行方式 |
| 10 | 无测试 | 正确性无法验证 | `tests/` 下 5 个单元测试，覆盖已知答案与异常输入 |

### 过程证据（git 提交序列）

重构与修 bug 刻意分为两次独立提交，以便从历史中区分"哪一步改变了结果"：


**公式修复的定位过程**（可复现）：

1. 观察到原输出 `r = 0.000156`，与 `head -10 sample_data.csv` 中两列明显的同涨同跌矛盾
2. 用 `numpy.corrcoef` 得到标准答案 `0.5634747`，相差 3600 倍 → 排除浮点误差，判定为公式结构性错误
3. 从量纲入手：`prod`（偏差乘积之和）为二阶量，`dx * dy`（两个偏差平方和相乘）为四阶量，量纲不匹配
4. 依据 `r = 协方差 / (σx·σy)`，标准差是方差的平方根，故分母需对 `dx*dy` 开方
5. 先在终端用一次性脚本验证猜想（`prod / sqrt(dx*dy)` → 0.5635），确认后再改代码
